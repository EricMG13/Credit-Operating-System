# CAOS Legacy Post-Mortem & Flaw Analysis — 2026-07-28

**Scope.** End-to-end audit of the legacy CAOS codebase (`caos/` — FastAPI server +
Next.js 16 frontend + Docker deploy stack; methodology corpora `Modular OS/` and
`corpus/DEPLOY_B_COWORK_SKILLS/`) to seed the Databricks greenfield rebuild specified
in `architecture/`, `roadmap/`, and `specs/`. Findings are ranked by **impact on the
rebuild**, not by legacy-operational severity.

**Method.** Five parallel dependency-mapping sweeps over the actual code (engine
assets; deploy/auth/execution plumbing; frontend; data model & security; audit-ledger
archaeology across `audit-backlog*.md`, `audit-log.md`, `qa_master_tracker.md`,
`.agent-reviews/redteam.md` (991 objection rows), `.review/run-*/findings.md`,
`caos/docs/qa/**`). Every claim below carries a `file:line` or ledger citation.
GitNexus MCP tooling was not attached in this session; impact analysis was done by
manual caller/callee review per the repo fallback convention.

## 1. Executive summary — what the rebuild must take seriously

1. **The assets are real and test-covered.** The deterministic engine, CP-5 gate,
   evidence chain, numeric guards, immutability hashes, approval gating, and intake
   security all exist as working, tested code with their design rationale written into
   docstrings. The checklist's asset-vs-plumbing split is confirmed by the code:
   port the assets near-verbatim **with their tests** (§9).
2. **The plumbing failed in exactly the ways the checklist predicts.** The hand-rolled
   executor/poller layer carries a documented double-execution race (§4-D); the
   auth/deploy stack is a personal-estate construction (oauth2-proxy Google, rclone,
   M365 Graph, self-hosted Postgres) with uncontrolled egress paths (§8).
3. **The single most-repeated bug class is numeric safety** (`bool(NaN) is True` —
   ~8 documented instances across 4 audit rounds) and it was only stopped by a shared
   `TypeGuard` + codified invariant + call-site sweep. The rebuild must make this a
   type-level property of the engine package from day one, not a review habit (§4-A).
4. **The legacy module-ID namespace is skewed against the normative DEPLOY_B corpus**
   (legacy `CP-2B` = downside is corpus `CP-2A`; legacy `CP-5` = the QA gate is corpus
   `CP-5A`). The corpus ships the authoritative alias register; the rebuild must adopt
   the canonical namespace and key parity mapping on `owned_object`, never on raw ID
   (§3 F-1).
5. **Reviewer severity inflation is a measured phenomenon in this repo** (28% of one
   audit round's premises factually wrong; 13 refuted vs 4 confirmed in the final full
   review). The rebuild's QA process must budget for adversarial *verification* with
   runnable repros, not just adversarial generation (§5).

## 2. Legacy architecture in one paragraph (for orientation)

One FastAPI container serves `/api` and a statically-exported Next.js UI, behind
`Caddy → oauth2-proxy (Google Workspace OIDC) → app → Postgres` (`caos/README.md:40-66`).
The engine routing index `server/engine/registry.py` declares 21 implemented
deterministic modules (+2 feature-flagged, +2 spec-only) in a layered DAG
(`L0→Orch→L1…L7→Infra`) executed by `server/engine/runner.py`; LLM synthesis flows
through one provider seam (`engine/llm_client.py`) over Anthropic/OpenRouter/Gemini
with a fixture mode when keys are absent. QA is the deterministic CP-5 phase
(`engine/gate.py` + `engine/lineage.py`). State is ~70 SQLAlchemy models in
`server/database.py` on self-hosted Postgres (+pgvector), with four hand-rolled
executors + a poller for background work. Analyst surfaces: Command Center, Pipeline,
Deep-Dive, Model Builder, Report Studio, Query/Ask, Monitor, plus Sector Review, RV
Screener, Sponsors, Portfolio Lab, IC Book.

## 3. Core architectural flaws, ranked by impact on the rebuild

Ordering rule: a flaw ranks higher the more it would corrupt or stall the rebuild if
ignored (parity risk > blocker risk > carry-forward quality risk).

### F-1 · Module-ID namespace skew between legacy engine and normative corpus — **parity-critical**

- Legacy registry IDs (`server/engine/registry.py:129-243`) and DEPLOY_B canonical IDs
  disagree systematically: legacy `CP-2B DownsidePathway` → canonical `CP-2A`; legacy
  `CP-2C EventCatalystRegister` → canonical `CP-2B`; … legacy `CP-4C
  CovenantCapacityCalculator` → canonical `CP-4A`; legacy `CP-5B
  EvidenceTraceValidator` → canonical `CP-5`; legacy `CP-5 ResearchIntegrityQA` (the
  deterministic gate) → canonical `CP-5A`; legacy `CP-6A/CP-6E` → canonical
  `CP-6/CP-6A`; legacy `CP-MON` → retired, replaced by `CP-EMAIL`.
- The corpus's authoritative mapping:
  `corpus/DEPLOY_B_COWORK_SKILLS/skills/rbot-orchestrator/references/MODULE_ID_ALIASES.md`
  — which itself mandates: *"ID-only alias resolution is prohibited; ambiguity blocks
  the handoff"* (resolve by legacy ID **plus** module name / `owned_object`).
- **Rebuild consequence.** Golden-master parity (checklist 9.1) diffs legacy output
  against rebuilt output *per module*. Diffing by raw ID would compare the downside
  module against the event register and "pass" or "fail" nonsense. The rebuild adopts
  the canonical namespace everywhere and implements the alias map as a typed,
  owned_object-keyed translation table in the parity harness (spec'd in
  `specs/phase-01-foundation.md`).

### F-2 · Hand-rolled executor/poller layer with a documented double-execution race — **replaced by platform (6.3)**

- `audit-backlog.round1-resolved.md`: *"QueueWorker re-claims a still-running run
  after a fixed 600 s lease (no heartbeat)… the race is real and nothing in the code
  prevents it. The only thing standing between 'fine' and 'double execution + status
  corruption' is the unverified assumption that a run never wall-clocks past 600 s."*
  Five-link failure chain: lease never renewed; re-claim predicate includes live runs;
  no `FOR UPDATE`; no in-flight dedup (a single worker can re-claim its own slow run);
  budget counted per-execution not per-run (fixed later by H-1: `runner.py:232` seeds
  `RunBudget.used` from `run.tokens_used`).
- Corruption path: `uq_fact` IntegrityError → `_mark_run_failed` overwrites a
  committed `complete` status → `failed`. Plus: *"a persistent per-tick DB error means
  the worker is alive but silently idle, queued runs never execute"*
  (`run_executor.py:75-86,237-238`).
- **Rebuild consequence.** This is the checklist's 6.3 verbatim: delete the four
  executors + poller; Databricks Workflows/Jobs own leasing, retries, and recovery.
  The rebuild must still port the *semantics* the executors carried: idempotency keys,
  cumulative-per-run token budget, stop-on-Blocked, and the `PipelineRun` audit trail.

### F-3 · Monolithic schema file and advisory ORM metadata — **schema-first rebuild required**

- `server/database.py` is 3,166 LOC holding ~70 models. Schema truth is
  Alembic-migrations-only (`init_db → upgrade head`, no `create_all`), so ORM
  `nullable=` and relationship metadata are advisory (`audit-backlog.md:606-618`
  investigated exactly this drift and confirmed the split). Legacy fixtures could not
  even be topologically sorted by SQLAlchemy because mappers don't declare ORM
  relationships (`tests/server/conftest.py:12-46` works around it with
  `PRAGMA defer_foreign_keys`).
- Migration-collision class: three documented incidents, including the near-catastrophe
  *"deployed `alembic_version` tables hold `fb2488db06e3`; renaming bricks every
  existing DB"* (`caos/docs/qa/FULL_CODEBASE_REVIEW_2026-07-23.md`).
- **Rebuild consequence.** The rebuild is schema-first: DDL files are the single
  source of truth (Lakebase Postgres DDL + Delta DDL in `dbx/schemas/`), constraints
  (FKs, CHECKs, uniques) live in the schema — the evidence chain (8.5) is enforced by
  schema, not convention — and ORM models are generated/validated against DDL by a
  round-trip test.

### F-4 · Hand-written 1,661-line `api.ts` mirror with recurring drift — **retired by 5.6**

- Confirmed drift class E instances: `REVIEW_MATRIX_FRONTEND.md:119` FE-9 — `api.ts:6`
  *still documents Databricks Apps + Databricks OAuth* (a previously-abandoned target)
  and *"this exact drift was already filed in the prior FE-9 pass and remains
  unfixed"*; a fixture missing `market_history` was the single live `tsc` break in the
  2026-07-23 full review.
- **Rebuild consequence.** Contract-first: FastAPI OpenAPI → generated TS client, CI
  fails on stale client (checklist 5.6). No hand-maintained API type surface anywhere.

### F-5 · Fail-open defaults on unknown states — **closed-vocabulary rule**

- ~7 instances (class C, §4): unknown `committee_status` renders green
  (`useLivePipeline.ts:30`); `nlquery._passes` fails open in three places
  (`nlquery.py:296-299,315` — *"a silently-unfiltered answer presented as
  authoritative"*); an early `roll_up_qa_status` ranked unknown status *better* than
  Passed before the fix; `hmac.compare_digest("", "") → True` when the signup code is
  unset (`auth.py:97`).
- The good pattern also exists and must be the rebuild's rule:
  `gate.py:76-84` ranks an unrecognized `qa_status` **worst** (`_QA_RANK.get(s, 99)`),
  and `gate.py:45-61` lets only an explicit `"Passed"` reach committee-ready.
- **Rebuild consequence.** Every status vocabulary in the rebuild is a closed enum in
  `dbx/contracts/`; every consumer maps unknown → the *most restrictive* state; UI
  renders unknown as blocked/attention, never success. Property tests assert this for
  every enum (phase 1).

### F-6 · Stringly-typed mode seams — **enum + config-object rule**

- The `.name == "live"` string switch on the synthesizer decides evidence-suppression,
  model pinning, and finding emission at four sites (`runner.py:242,349,464`,
  `bindings.py:96`).
- The brittle exact-string `environment == "production"` gates cookie security, weak-
  secret enforcement, and docs closure simultaneously — *"a single mistype downgrades
  several controls at once"* (`audit-backlog.md:186-192` S5; dead-but-live Databricks
  path `identity.py:104` shares the same root).
- **Rebuild consequence.** Modes are enums; environment posture is a validated config
  object computed once at boot (fail-closed on unknown), never scattered string
  comparisons. The rebuild targets Databricks Apps for real, so the legacy dead
  Databricks path is superseded rather than resurrected.

### F-7 · Two parallel period/date systems that never converged — **single period kernel**

- `engine/periods.py` (the audited, guard-bearing kernel) vs
  `model_engine_v2.py:70-100` (`_period_order_key`, `_shift_months`) — a second,
  independent implementation of period ordering and month arithmetic inside the Model
  Engine. The period-ordering bug class (§4-B) took **two sweeps** to close because
  call sites bypassed the kernel (`earnings.py:41`, `peers.py:52`, `querygraph.py:548`
  — the third site was missed by the first sweep).
- **Rebuild consequence.** One period kernel in the pure engine package
  (`dbx/engine/periods.py`), property-tested; Model-Builder math imports it. Any
  second implementation is a review-rejectable offence (stated in `CLAUDE.md`).

### F-8 · Process-local state assumed global — **platform-state rule**

- Rate limiter is process-global (autouse test reset `_reset_rate_limit`), run-creation
  lock is a lazily-initialized asyncio lock with a check-then-set race
  (`routes/runs.py:40-44`), budget coordination is an `asyncio.Condition` (per
  process), BM25 corpus cache is per-process keyed on a version tuple. The DB-level
  partial unique index `uq_runs_issuer_active` (`database.py`, on `(issuer_id)` where
  status queued/running) exists precisely because the in-process lock cannot span
  replicas.
- **Rebuild consequence.** On Databricks (serverless app replicas + jobs), *only*
  DB/platform-visible state counts: idempotency and single-active-run stay DB-enforced;
  rate limits live at the gateway/edge (3.3, 7.4); caches are read-through and
  versioned. No in-process lock may guard a cross-request invariant.

### F-9 · Retrieval scale cliffs and structure-destroying chunking

- Cross-issuer query paths `SELECT` every chunk of in-scope issuers and re-tokenize
  per query — O(corpus) memory/CPU, flagged as *"a latency/memory cliff at scale"*
  (`audit-log.md:330-338`); BM25 scan cap 5,000 chunks ×8 call sites
  (`retrieval.py`); covenant scan cap 2,000 rows silently truncates
  (`querygraph.py:961,977`).
- Fixed 2,400-char chunking: *"financial tables and covenant clauses fragment across
  chunk boundaries, degrading BM25 retrieval quality on exactly the structured content
  the tool cares about"* (`ingest.py:177`).
- **Rebuild consequence.** Chunking/retrieval moves to the Delta silver layer with
  structure-aware chunking for tables/clauses and DB-side prefilters; caps become
  explicit, surfaced limitation flags (never silent). This is a Phase 4 design
  requirement, with the legacy caps kept initially for parity and the improvements
  logged as deviations if they change retrieval-dependent outputs.

### F-10 · Seeded-demo vs live blending — **provenance-visible rule**

- Committee tear-sheet printed **seeded** tranche dollars contradicting canonical
  facts (equity overstated ~$695M; `.review/run-2026-06-27` F2 HIGH); phone triage
  showed a seeded "26/26 modules" as if live (`REVIEW_MATRIX_FRONTEND.md:64` FE-3);
  Deep-Dive bespoke tabs always showed ATLF fixtures (`audit-log.md:25-43`).
- Legacy already grew the right server-side control: fixture-derived numbers for a
  non-demo issuer are tagged `provenance="demo_fixture"`, raise a MATERIAL finding,
  and stamp `DEMO_FIXTURE_LIMITATION` (`metrics.py:194-197`, `runner.py:490-496`).
- **Rebuild consequence.** Provenance is a first-class column end-to-end; every
  surface renders fixture/demo provenance visibly (checklist 3.6 keeps fixture mode,
  so the contamination guard must port with it, tests included).

### F-11 · Middleware stacking latency collapse (solved once, must not regress)

- Four stacked Starlette `BaseHTTPMiddleware` layers collapsed issuer-probe p95 to
  891 ms at 300 users; three plausible root causes were falsified before cProfile
  found the real one; consolidation to one raw ASGI layer → 129 ms
  (`caos/docs/qa/perf/FIRST_FAULT_STRESS_REPORT_2026-07-19.md`).
- **Rebuild consequence.** The rebuilt FastAPI app uses at most one consolidated ASGI
  middleware for identity/chokepoint/access-log; a perf budget test guards p95.

### F-12 · Typing debt concentrated exactly in the credit-math modules

- `caos/server/mypy.ini` excludes 9 modules — `adjusted, council, covenants,
  edgar_cp1, reported_cp1, peers, planner, querygraph, synth` — *every one a
  credit-math or routing module*; the exclusion list never shrank across three
  coverage expansions.
- **Rebuild consequence.** The pure engine package is fully typed from day one
  (mypy --strict in CI); dict-shaped payloads become typed models in
  `dbx/contracts/`. No exclusion list for engine code.

### F-13 · Frontend complexity without test coverage — **port with tests-first**

- 87 functions over complexity threshold (25 critical); worst offenders
  `GraphCanvas.tsx NodeMark` (CRAP 1190), `pipeline/page.tsx` (1122),
  `UploadWizard.tsx` (1056); refactor explicitly blocked because *"istanbul matched
  136/1452 functions, so a safe refactor needs the components under test FIRST"*
  (`fallow-cleanup-log.md:46-52`); Monitor cluster named *"worst in repo"*
  (2026-07-23 review).
- **Rebuild consequence.** The Vite port (Phase 5) rebuilds surfaces against the
  generated API client with component tests as the port vehicle; the worst-complexity
  clusters (Monitor, Pipeline, Upload) are decomposed per the surface specs rather
  than transliterated.

### F-14 · Unbounded-resource intake paths

- Uploads buffered fully in RAM (250 MB cap × concurrent uploads; `ingest.py:38`);
  **no timeout on pypdf parse** off-thread → threadpool exhaustion → async handlers
  starve (`caos/docs/qa/STRESS_TEST_PLAN.md:100-110`, HIGH, never closed); report
  assembly and profile-delete endpoints have no rate limit; single uvicorn worker
  without `limit_concurrency` (slowloris).
- A deploy-side landmine: the app image has no `/vault` directory, so a pristine
  volume mounts root-owned and **212/212 uploads failed** on a fresh host
  (`PRE_DEPLOYMENT_CAPACITY_2026-07-22.md`).
- **Rebuild consequence.** Intake becomes a Workflows job over UC Volumes with
  streaming writes, per-stage timeouts, and platform resource ceilings (checklist
  7.3's ceilings port as config), removing the in-process buffering class entirely.

### F-15 · Day-count conventions absent (domain simplification, undocumented)

- Zero hits for `30/360`, `ACT/360`, `Actual/365`, `day_count` anywhere. All interest
  math uses flat `months/12` annualization (`model_engine_v2.py:903`). For a
  leveraged-credit tool computing cash interest, coverage, and PIK accretion this is a
  silent modelling simplification with no documented acceptance.
- **Rebuild consequence.** Phase 1 pins the current behaviour in the parity harness
  (parity first), and the simplification is documented as accepted-for-parity in
  `DEVIATIONS.md` terms — introducing real day-count support later is a logged
  deviation with owner sign-off, because it deliberately breaks numeric parity.

### F-16 · Corpus-level ordering defect: structural-priority map consumed before it is produced

- `Modular OS/CP-4D/SYSTEM_REFERENCE.md:8`: CP-4D owns the structural-priority map;
  CP-3B (recovery waterfall) consumes it but *"CP-3B runs earlier in the canonical
  order — consumption applies on the next run or requires moving CP-4D ahead"*. The
  DEPLOY_B route graph resolves this (canonical `CP-4B → CP-4A, CP-4C, CP-6`; CP-3A
  consumes CP-4B *"by reference"*), but the legacy engine's layer order still has the
  legacy shape.
- **Rebuild consequence.** The rebuilt DAG uses the DEPLOY_B route graph verbatim
  (`ROUTE_GRAPH.md` v2.6); the parity harness must therefore compare *per-module
  outputs on identical inputs*, not whole-pathway traces, wherever the corpus DAG and
  legacy DAG disagree — those DAG differences are logged as deviations, not silently
  absorbed.

### F-17 · Demo-fixture monolith and token triplication in the frontend

- `src/lib/command/data.ts` (18,008 LOC) + `market-data.json` (11,174 LOC) —
  **29,182 LOC of ATLF demo fixture, 34% of the non-test frontend**, hard-depended on
  by Command Center and shipped separately by the Dockerfile (`deploy/Dockerfile:61-62`).
  Combined with §3 F-10 (seeded-vs-live blending) this is the structural cause of the
  demo-bleed class.
- Design tokens exist in **three** unsynchronized copies (`globals.css` `:root`,
  `tailwind.config.js:7-31`, `src/lib/color-tokens.ts`); the bespoke `.tabular`
  utility (mono family + `tnum`) has 1,051 uses and is not Tailwind's `tabular-nums`.
- `nav.ts` carries dead metadata for a dynamic route that does not exist
  (`/issuers/[issuerId]`, `nav.ts:80,105-110`).
- **Rebuild consequence.** Fixtures move out of the app bundle into the fixture-mode
  data layer (3.6) keyed by provenance; tokens collapse to a single source (CSS
  variables) consumed by Tailwind config; the port carries `.tabular` explicitly.

## 5. Failed patterns and state/control couplings (documented by the repo itself)

1. **Turbopack persistent dev cache** — Critical: *"41–58 GB cache growth and
   system-wide write-pressure failures"* (RT-2026-07-15-263); locked off via
   `next.config.js` and standing orders. Rebuild note: the Vite toolchain removes the
   class; keep the lesson (no persistent opaque build caches without a size ceiling).
2. **Starlette `BaseHTTPMiddleware` stacking** — the 85.5% p95 collapse (§3 F-11);
   three wrong root causes falsified first. Rebuild: one raw ASGI layer, perf-budget
   test.
3. **Dead-platform code with live security semantics** — abandoned Databricks path
   still classified requests as "deployed" (`identity.py:104`) while secret
   enforcement keyed on `== "production"`. Rebuild: environment posture object (§3 F-6).
4. **Freeze-discipline coupling** — one dependency advisory (DEF-002, still OPEN in
   `qa_master_tracker.md:166`) made *every* CI run repo-wide fail while the frozen
   candidate awaited re-freeze. Rebuild: dependency gates block *merge*, not the whole
   pipeline for unrelated work; allowlists carry expiry dates.
5. **Registry acyclicity added late** — the DAG had no self-check until an audit
   found a silent-fallback path (`runner.py:97-108` pre-fix) that would mask a cyclic
   registry. Now import-time validation fails loud (`registry.py:263-290`). Rebuild
   ports the loud version; Workflows adds platform-level DAG validation on top.
6. **pip constraints reject `[extras]`** — D9 image-integrity pinning attempt
   reverted; proper fix is a compiled lockfile. Rebuild: uv/pip-compile lockfiles from
   Phase 1 (also feeds SCA, 5.2).
7. **Parallel-WIP contamination** — repeated incidents of concurrent human/agent edits
   corrupting review baselines; codified as explicit-paths-only staging. Rebuild keeps
   the convention (CLAUDE.md).
8. **Tooling false-positive tax** — regex a11y scanner produced 1,169 non-actionable
   findings vs a clean rendered-axe matrix; two other scanners demoted to advisory.
   Rebuild: runtime-verified checks (axe against rendered surfaces) are the gate
   (9.3); static regex scanners advisory only.
9. **Session-boundedness declared in two places** — `session_bound` on the module spec
   *and* a legacy `_SESSION_SYNTH` set both live (`registry.py:112` vs
   `runner.py:303`). Rebuild: single declaration point (the registry), enforced by a
   registry-consistency test.

## 7. Scale & performance envelope (measured; sets rebuild budgets)

- **Measured capacity** (frozen image, 2026-07-22): 300 issuers / 600 documents /
  2,400 metric facts; 25,630 requests in 20 min steady, 0 unexpected failures;
  p50 18 ms / p95 42 ms / p99 61 ms; memory ~765 MiB peak of 4 GB.
- **First-fault ceiling**: 320 users (issuer-probe p95 4,000 ms) pre-middleware-fix;
  post-fix 33–147 ms at the same load. Budget: **500 ms p95** on issuer probe.
- **Hard caps in code** (port as explicit config + limitation flags): BM25 scan 5,000
  chunks; covenant scan 2,000 rows; NL-query 50 results; upload 250 MB; chunk 2,400
  chars; run token budget 120,000; deep-research 4 continuations / 16,000 max tokens.
- **Known unmitigated vectors** (all HIGH, never closed — rebuild must close by
  construction): unlimited `POST /runs/{id}/report` assembly; no pypdf parse timeout;
  no `limit_concurrency`; unbounded `list_runs`.
- Full corpus sweep (28 issuers, EDGAR facts) ≈ 7 s; server+stress+cohort pytest
  ≈ 370 s for 2,934 tests — the parity harness inherits these fixtures and budgets.

## 8. Transfer-blocking findings (checklist P1 lens)

A telling frame from the legacy deploy docs themselves — `caos/deploy/README.md:1-6`:
*"Runs CAOS on a single Linux box with Docker, **replacing the Databricks App**. …
oauth2-proxy provides the edge auth **that Databricks used to give us**."* The
off-estate stack is a hand-built re-implementation of platform primitives the rebuild
gets back natively.

### 8.1 · P1 blocker inventory — what is deleted or replaced

**Identity (2.1, blocker).** Google Workspace OIDC via oauth2-proxy
(`deploy/oauth2-proxy.cfg:19` `provider = "google"`; upstream `app:8000`; personal
OAuth client via `OAUTH2_PROXY_CLIENT_ID/_SECRET`). Caddy injects
`X-Edge-Authorization {$EDGE_PROXY_SECRET}` and strips client-supplied identity
headers (`deploy/Caddyfile:28-46`). **Disposition:** delete the edge pair; Databricks
Apps workspace SSO supplies identity. *Carry forward as defence-in-depth:* the raw-ASGI
chokepoint (`main.py:347-371`, both-sides-encoded `hmac.compare_digest` — 2.5), the
HMAC session + mandatory-`exp` + `token_version` revocation epoch
(`identity.py:96-145`, verified per request at `identity.py:209-210` — 2.4), the
role CHECK + fail-closed `require_write_role` (`identity.py:81-93`, DB CHECK at
`database.py:348` — 2.2), and the forwarded-email vs cookie cross-check
(`identity.py:220-221`).

**Model access (3.1/3.2, blocker).** Direct provider keys `ANTHROPIC_API_KEY` /
`OPENROUTER_API_KEY` / `GEMINI_API_KEY` (`config.py:91,97,120`) consumed through the
seam (`engine/llm_client.py`, adapters `openrouter.py`/`gemini.py`). Three findings
beyond the headline replacement:
1. **Egress-gate carve-outs:** `nlquery.py:266,337` and `scenario.py:203` call the
   LLM on key-presence alone, skipping `document_egress_allowed()` — an undocumented
   exception to a policy whose own docstring says *"Every lane that can carry that
   material must consult this predicate"* (`config.py:356-359`). The rebuild closes
   this **by construction**: the egress predicate is enforced inside the single
   gateway seam, so a lane cannot skip it.
2. **Metadata leak:** `engine/openrouter.py:171` sends
   `HTTP-Referer: https://github.com/EricMG13/Credit-Operating-System` + `X-Title:
   CAOS` to OpenRouter on every call — names the private repo to a third party.
3. **Ambient-key hazard:** the Gemini SDK would read `GOOGLE_API_KEY`/`GEMINI_API_KEY`
   from the process env if not passed explicitly (`gemini.py:58-61`) — an env var the
   `Settings` object never saw could enable egress. Gateway-only credentials (3.2)
   eliminate the class.
**Disposition:** all lanes point at Mosaic AI Gateway / Model Serving external-model
endpoints through the ported seam; no vendor SDKs remain in the dependency tree.

**Data egress (4.2/4.3/4.4, blockers).** Ranked inventory of every off-host path:
1. `rclone` backup-sync container — the only remote-credential holder; ships **full
   Postgres dumps + the entire document vault** to an operator-chosen, unvalidated
   remote (`deploy/backup_sync.sh:69-72`; compose secret
   `/run/secrets/backup_rclone_config`). **Delete (4.3);** replace with Lakebase
   managed backups + Delta (6.6).
2. Obsidian vault export (`server/vault_export.py`, 616 LOC) — one-way Markdown
   mirror to `VAULT_EXPORT_DIR`; recursive raw-content redaction exists
   (`_RAW_CONTENT_MARKERS`, `:59-74`) but the route comment itself flags that **any
   authenticated analyst can export any run** (`routes/runs.py:713`), and a synced
   target directory exfiltrates. **Delete (4.3).**
3. Deep Research uses Anthropic's server-side `web_search` tool with **no
   `allowed_domains` restriction** (`deepresearch.py:256`; parameter unused).
   **Rebuild:** gateway guardrails + explicit domain allowlist config (4.2/3.5).
4. `CAOS_DOCUMENT_EGRESS_ENABLED` master gate (`config.py:141,354-364`, default
   false; *"provider keys alone never authorize confidential-document egress"*) — a
   genuine asset; **ports as the app-side layer of 4.2** beneath the gateway boundary.
5. EDGAR fetches (`server/edgar.py`, SSRF-hardened host allowlist, ≤6.67 req/s
   aggregate throttle) — inbound-only, keep behind the ingestion job.
6. MCP EDGAR wrapper (`caos/mcp/edgar/server.py:34-38`) **forges
   `X-Forwarded-Email` with no edge credential** — a working impersonation client
   wherever the edge check is off. **Delete;** rebuilt equivalent must use real
   platform auth (on-behalf-of), not header forgery.

**Hosting/repo (5.1/6.1, blockers).** Eight-service self-managed Docker stack
(`deploy/docker-compose.yml`: db, vault-init, app, oauth2-proxy, caddy, backup,
backup-sync, clamav) on a single box; personal GitHub repo (named to a third party by
the OpenRouter referer above). **Disposition:** Databricks App (serverless) +
Lakebase + Workflows via Asset Bundles; repo migrates to the enterprise org (5.1 —
org-side action, tracked in ROADMAP). The accepted-risk register's *"66 HIGH/CRITICAL
OS CVEs in the app image, all with no fixed version in Debian trixie"* dissolves with
the self-managed image.

These are places where the checklist's "CAOS relevance" column describes capability
the code does not actually have. The rebuild plans around the *code* reality:

1. **4.4 — there is no live M365 Graph mail sync.** Exhaustive sweep (`graph.microsoft`,

   sensitivity labels, no per-issuer ACLs, no durable read-audit table; the only read

3. **CP-MODEL / CP-SNAP identifiers do not exist in legacy code** (zero grep hits).

   `report_exports.py`. The corpus supplies the canonical identity and payload

4. **2.3 — there are no system-to-system credentials to migrate** beyond provider

   port.
5. **Numbers drift:** `api.ts` measures 1,643 lines (checklist: 1,661) plus ~60 path
   literals across satellite clients; file counts 547 py / 556 ts+tsx vs the
   checklist's 476/618 snapshot. The drift classes the checklist names are all

   the only callers of `alert_dispatch.dispatch_once` are tests. The C3 watch-rule
   evaluation/delivery lane is **half-built by design** and maps cleanly onto
   Workflows schedules (6.3) rather than porting a poller.
